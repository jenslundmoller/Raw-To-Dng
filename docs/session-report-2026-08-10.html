The original question

Is NEF open, and does reading it require a licence?

NEF is proprietary with no published specification, but reading it requires no licence from Nikon. Every open-source decoder — dcraw, LibRaw, darktable, RawTherapee, dnglab — is reverse-engineered, and no raw decoder has ever been sued. Nikon's own SDK is approval-gated, Windows and macOS only, and licence-incompatible with open source.

DNG is the opposite: Adobe publishes the specification with a royalty-free, worldwide patent grant for compliant implementations.

The one real legal wall

Nikon's High Efficiency modes (HE and HE*) on the Z9, Z8, Zf, Z6III and ZR use intoPIX TicoRAW, which is patented. Reverse engineering does not cure a patent, so an open-source decoder cannot legally ship without a licence. This is why LibRaw, dnglab and darktable all lagged on those bodies.

That exclusion does not affect the target camera. The Nikon Z 6 writes lossless-compressed NEF, fully supported and unencumbered.

Feasibility, established before designing

A spike, not an estimate

The hard part of raw conversion is not parsing — it is the per-model calibration database: colour matrices, black and white levels, active areas, CFA layouts. Getting those wrong produces wrong colour, and none of it is derivable from the file. That is why writing a converter from scratch is a multi-year commitment.

A spike linking rawler 0.7.2 settled it in under an hour: all eight sample NEFs converted to valid DNG 1.6 with full dual-illuminant colour matrices and white balance intact. The remaining work was entirely GUI.

What was built

Rust · GTK4 · libadwaita · rawler linked directly

A single self-contained binary, no runtime dependencies beyond the GNOME stack. Linking rawler rather than shelling out to the dnglab CLI gives real cancellation, per-file progress and identical conversion correctness — it is the same engine.

Safety rules, treated as invariants

  1. Sources are never deleted, moved or modified. There is no "delete originals" option at any point.
  2. Atomic writes. Output goes to a hidden .part file, renamed only on success. A crash, cancel or full disk never leaves a truncated DNG that could later pass for a good one.
  3. Never silently overwrite. An existing target is skipped unless explicitly opted into.

Rule 2 was tested adversarially: a hard write failure under a file-size cap killed the process outright with SIGXFSZ — and what survived was a .part file, never a .dng. The invariant held even against process death.

Verification — the centrepiece

Because the workflow ends in deleting the originals

The intended use is to convert a large batch and then delete the NEFs. That makes "finished without errors" a claim that has to mean provably correct, not nothing crashed. A file can be written successfully and still be wrong.

After writing, the .part file is decoded again and compared against the source. Only a match is renamed to .dng. Verification runs before the rename, so a DNG never exists in an unverified state.

Every tolerance was measured, not guessed. White balance is the sole non-exact comparison because DNG stores AsShotNeutral as rationals; the observed drift is 1.4 × 10−5 relative, and the bound is set at 1 × 10−4 — above the drift, still thousands of times tighter than any visible difference.

Why not a file-size check

A size heuristic was proposed and rejected on evidence. Compression ratio depends on image content, so a flat frame can legitimately compress very small while a corrupt file lands at a plausible size. The test suite proves the gap: flipping bits deep inside a valid DNG leaves it exactly the same size with an intact header.

Defects found

Five fixed · two near-misses worth recording

Every portrait photograph was rejected

Reported by user

Symptom verification failed: orientation differs (original Normal, written Rotate90)

Cause rawler's NEF decoder never populates RawImage.orientation, leaving it Normal, while its DNG decoder reads the real tag. The comparison was between a field only one side fills in. All eight test fixtures were landscape, so it never surfaced.

Verdict The DNG was correct all along — the EXIF orientation tag reads 6 in both files, confirmed from the bytes. The failure was in the safe direction: good files rejected, none wrongly accepted, no DNG written.

Stale "2 failed" after clearing the queue

Reported by user

Cause The indicator was tracked alongside the queue and set once during a run, never re-evaluated. Clearing emptied the queue and forgot it existed.

Hidden sibling The filter also stayed attached, so files added after clearing would have been hidden entirely — an empty list above a non-empty queue.

Fix State is now derived from the queue at every mutation point, which removes the class of bug rather than the symptom.

Crash on launch from the app grid

Caught by testing

Cause set_default_icon_name ran before GTK was initialised and panicked. Running the binary directly had masked it — it only appeared via the desktop entry, the exact path of daily use.

Installer hijacked default apps for 13 raw formats

Caught by testing

Cause Declaring MIME types made the converter a candidate default handler, displacing Darktable. Double-clicking a NEF would have opened a converter instead of an editor.

Fix The installer now records existing defaults and restores anything it displaces. The converter stays reachable under Open With.

Install instructions were unusable

Reported by user

Cause The README said ./install.sh with no clone step and no mention of installing Rust.

The real trap apt install rustc on Ubuntu 24.04 gives 1.75; this needs 1.88. Anyone following instinct would hit a confusing compiler error and stop.

Lens metadata appeared to be lost — it was not

Near-miss

Comparing through rawler showed lens_make, lens_model and lens_spec all returning None from the DNG. That reads as "conversion drops your lens data" and would have been reported as data loss.

Reality Inspecting the bytes showed the DNG carries all of it. The gap is in rawler's DNG reader. Two real differences did emerge, both of which would have caused false alarms: case is normalised (NIKON → Nikon) and rationals are re-encoded (240/10 → 24/1).

Panic isolation was never observed firing

Unproven claim

catch_unwind wraps every conversion because dnglab's README documents panicking as intended behaviour on malformed input. A truncated real NEF produced a clean decode error instead, so the guard has never been seen to trigger. It stays as defence-in-depth, recorded as untested rather than claimed as proven.

Decisions and their reasons

Choices that shaped the result

Camera support was widened to every manufacturer

Originally Nikon-only. The accepted extensions are now queried from rawler at runtime rather than hardcoded — 724 models across 19 manufacturers, so support tracks the library. DNG is deliberately excluded as input, being the app's own output.

Flathub is not available

Flathub's requirements state that "applications containing AI-generated or AI-assisted code, documentation, or any other content are not allowed", and that submission pull requests must not be opened using AI tools. This code was written with AI assistance, so submitting it would misrepresent its provenance. The README discloses this openly.

Self-hosting a Flatpak repository was considered and dropped: apps outside Flathub are invisible unless each user adds the remote manually, so the hosting work buys no discoverability.

Distribution instead

A GitHub release with a prebuilt binary. Three commands, no Rust, no compiling — verified by downloading it back from GitHub and installing it with cargo removed from PATH. 

tar xzf rawtodng-0.1.0-x86_64-linux.tar.gz
cd rawtodng-0.1.0-x86_64-linux
./install.sh

Known limits

Stated plainly rather than buried

  • Nikon HE/HE* is unsupported — patented TicoRAW. Those bodies shooting Lossless Compressed work normally.
  • Only Nikon Z 6 files have been converted end-to-end. Other manufacturers rest on rawler's camera database and the extension tests. Verification is the safety net: a model-specific problem surfaces as a failure, not a silently wrong DNG.
  • Verification proves correctness at write time, not durability. Bit rot after conversion is outside the app's reach.
  • Nikon maker notes are not compared — Picture Control, Active D-Lighting. rawler does not expose them. Darktable does not read them either; Nikon's own software would.
  • The GUI has never been seen by its author. GNOME blocks dbus screenshots from unsandboxed apps, so every visual detail was confirmed by the user, not observed directly.
Standing recommendation

On the first large batch, keep the originals until a handful of DNGs have been opened in Darktable. Verification proves the data matches; your eyes confirm the rendering is what you expect.
